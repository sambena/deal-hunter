Deal Hunter API

Back to Deal Hunter

Everything the Deal Hunter page does is available to your own apps and scripts as JSON.

  • Address: the API port on the machine running Deal Hunter, e.g. http://192.168.86.82:8781. It's meant for your home network or VPN, not the internet.
  • Sign in: POST /api/auth/login with {"email", "password", "device_name": "Pixel 10"} (no header needed) returns {"token": "dht_…", "user": {"id", "name", "email", "role"}}. Send the token with every call as Authorization: Bearer TOKEN. Each device gets its own token; see and revoke them in Settings > Your account. POST /api/auth/logout revokes the one in use; GET /api/me says who you are.
  • Everything is per person: you only ever see and change your own watches, finds and devices.
  • Wrong email or password gives 401 and repeated failures 429, both with a readable {"error"}.
  • Old single key: the admin's key from Settings > API still works as a Bearer token (acting as the admin) while apps move to sign-in.
  • Writes (POST/PUT/DELETE) send a JSON body with Content-Type: application/json.
  • Errors come back as {"error": "..."} with an HTTP status (401 = missing or wrong key).
  • The API port can't read or change settings or keys; do that on the Deal Hunter page.
curl -H "Authorization: Bearer YOUR_KEY" http://192.168.86.82:8781/api/listings?status=new

curl -X POST -H "Authorization: Bearer YOUR_KEY" -H "Content-Type: application/json" \
  -d '{"name": "RTX 3060 12GB", "query": "rtx 3060 12gb -8gb", "max_price": 250}' \
  http://192.168.86.82:8781/api/watches

PowerShell: Invoke-RestMethod -Headers @{Authorization="Bearer YOUR_KEY"} http://192.168.86.82:8781/api/state

Finds (listings)

CallWhat it does
GET /api/listingsFinds, newest first (max 500). Options: watch=ID, status=active|new|seen|starred|dismissed|all (default active), sort=newest|price|deal, since_id=N (only finds added after id N, oldest first, any status unless you pass one: for apps that alert, so nothing is announced twice). Each has title, price, shipping, total, url, image, location, condition, source, deal_pct (0.25 = 25% under typical), first_seen, seen_at.
POST /api/listings/IDSet status: {"status": "seen"|"starred"|"dismissed"|"new"}.
POST /api/listings/mark-seenMark all new finds seen; {"watch": ID} for one watch.
POST /api/listings/ID/ask-aiAI verdict on a find (uses your AI settings and monthly limit).

Watches

CallWhat it does
GET /api/stateWatches (with new/total counts and best price), My hardware, settings (secrets shown only as true/false), poller status, AI budget.
POST /api/watchesCreate: name, query required; optional exclude (list), min_price, max_price, condition (any|used|new), sources (list), machine_id, notes, check (false = don't search right away). Returns {"id", "new", "errors"}.
PUT /api/watches/IDChange any of the fields above, e.g. {"enabled": false}.
DELETE /api/watches/IDDelete a watch and its finds.
POST /api/watches/ID/runSearch this watch now.
POST /api/pollStart a check of every watch in the background.

Query syntax: every word must be in the title; a|b either; "exact phrase"; -word excludes. Sources: ebay, ebay_local, ksl, reddit, slickdeals, buildapcsales, bestbuy.

My hardware

CallWhat it does
POST /api/machinesAdd a device: name, kind (pc, server, tv, monitor, phone, tablet, audio, network, console, printer, appliance, smart home, vehicle, other), make, model, year, msrp, purchased (YYYY-MM-DD), price_paid, custom (your own fields: list of {"label", "value"}), parts (PCs: list of {"category", "model"}), notes. All but name are optional; new fields may be added over time, so ignore ones you don't know.
PUT /api/machines/ID / DELETEChange (send the whole device) or delete.
POST /api/machines/ID/specsFill in a PC's parts from {"text": ...}: the Get specs command's output, or other text with "use_ai": true.
POST /api/machines/ID/suggestUpgrade ideas; {"use_ai": true} for AI.
POST /api/radarDeal radar proposals for every device; {"use_ai": true} includes non-PCs.
