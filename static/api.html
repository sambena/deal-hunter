Deal Hunter API

Back to Deal Hunter

Everything the Deal Hunter page does is available to your own apps and scripts as JSON.

  • Address: the API port on the machine running Deal Hunter, e.g. http://192.168.86.82:8781. It's meant for your home network or VPN, not the internet.
  • Sign in: POST /api/auth/login with {"email", "password", "device_name": "Pixel 10"} (no header needed) returns {"token": "dht_…", "user": {"id", "name", "email", "role"}}. Send the token with every call as Authorization: Bearer TOKEN. Each device gets its own token; see and revoke them in Settings > Your account. POST /api/auth/logout revokes the one in use; GET /api/me says who you are.
  • Everything is per person: you only ever see and change your own watches, finds and devices.
  • Wrong email or password gives 401 and repeated failures 429, both with a readable {"error"}.
  • Old single key: the admin's key from Settings > API still works as a Bearer token (acting as the admin) while apps move to sign-in.
  • Writes (POST/PUT/DELETE) send a JSON body with Content-Type: application/json.
  • Errors come back as {"error": "..."} with an HTTP status (401 = missing or wrong key).
  • The API port can't read or change settings or keys; do that on the Deal Hunter page.
curl -H "Authorization: Bearer YOUR_KEY" http://192.168.86.82:8781/api/listings?status=new

curl -X POST -H "Authorization: Bearer YOUR_KEY" -H "Content-Type: application/json" \
  -d '{"name": "RTX 3060 12GB", "query": "rtx 3060 12gb -8gb", "max_price": 250}' \
  http://192.168.86.82:8781/api/watches

PowerShell: Invoke-RestMethod -Headers @{Authorization="Bearer YOUR_KEY"} http://192.168.86.82:8781/api/state

Finds (listings)

CallWhat it does
GET /api/listingsFinds, newest first (max 500). Options: watch=ID, status=active|new|seen|starred|dismissed|all (default active), sort=newest|price|deal, since_id=N (only finds added after id N, oldest first, any status unless you pass one: for apps that alert, so nothing is announced twice). Each has title, price, shipping, total, url, image, location, condition, source, deal_pct (0.25 = 25% under typical), first_seen, seen_at.
POST /api/listings/IDSet status: {"status": "seen"|"starred"|"dismissed"|"new"}.
POST /api/listings/mark-seenMark all new finds seen; {"watch": ID} for one watch.
POST /api/listings/ID/ask-aiAI verdict on a find (uses your AI settings and monthly limit).

Watches

CallWhat it does
GET /api/stateWatches (with new/total counts and best price), My Stuff, settings (secrets shown only as true/false), poller status, AI budget.
POST /api/watchesCreate: name, query required; optional exclude (list), min_price, max_price, condition (any|used|new), sources (list), machine_id, notes, check (false = don't search right away). Returns {"id", "new", "errors"}.
PUT /api/watches/IDChange any of the fields above, e.g. {"enabled": false}.
DELETE /api/watches/IDDelete a watch and its finds.
POST /api/watches/ID/runSearch this watch now.
POST /api/pollStart a check of every watch in the background.

Query syntax: every word must be in the title; a|b either; "exact phrase"; -word excludes. keep_cheapest on a watch (a number, or null for all) keeps only that many cheapest finds; the rest get status pruned (hidden, never new). Turning a watch off (PUT with enabled: false) marks its new finds seen and returns marked_seen. A watch's color is "#rrggbb" or null (then apps pick from the shared palette by watch id). A watch with kind: "vehicle" (default "item") is a car or truck search: year_min, year_max, max_miles; it uses only ebay, ebay_local, craigslist, offerup (and ksl_cars), and its finds carry year, miles, title_status (salvage/rebuilt/branded or null). Watches and devices have a category (tech, cars or home; watches also category_choice, null = automatic; send category only to pick one). Each person's focus setting (all, tech, cars, home) is theirs to show just one category. A watch with kind: "clothing" has size (text) and department (men, women, kids or null); its finds carry size, and it uses ebay, ebay_local, poshmark, craigslist, offerup, ksl, slickdeals. Each person's sizes setting is {department, shoe, top, pants}. GET /api/listings sort: newest, price, price_desc, deal; for cars miles, year_desc, year_asc, make; for clothes size (finds without that value last). Vehicle finds carry make. It also takes source: one source key or several, comma separated (ebay,ebay_local). AI review: GET /api/ai/choices → {choices: [{provider, model, label, free, current}], max_review}; POST /api/ai/estimate with action: "review", listing_ids, instructions, provider, model; POST /api/ai/review {listing_ids, instructions, provider, model, hide} → {reviewed, good, ok, skip, hidden, hidden_ids, unanswered, watch_changes: [{watch_id, watch_name, changes, reason}]} (apply a change with PUT /api/watches/ID and its changes; undo a hide with POST /api/listings/ID {status: "seen"}). Sources: ebay, ebay_local, ksl, ksl_cars, poshmark, craigslist, offerup, reddit, slickdeals, buildapcsales, bestbuy.

My Stuff

CallWhat it does
POST /api/machinesAdd a device: name, kind (pc, server, tv, monitor, phone, tablet, audio, network, console, printer, appliance, smart home, vehicle, other), make, model, year, msrp, purchased (YYYY-MM-DD), price_paid, custom (your own fields: list of {"label", "value"}), parts (PCs: list of {"category", "model"}), notes. Vehicles also take vin and odometer (changed only when sent). All but name are optional; new fields may be added over time, so ignore ones you don't know.
PUT /api/machines/ID / DELETEChange (send the whole device) or delete.
POST /api/machines/ID/specsFill in a PC's parts from {"text": ...}: the Get specs command's output, or other text with "use_ai": true.
POST /api/machines/ID/suggestUpgrade ideas; {"use_ai": true} for AI.
POST /api/radarDeal radar proposals for every device; {"use_ai": true} includes non-PCs.
Parts that fitA watch whose machine_id is a vehicle with make, model and year searches eBay Motors Parts & Accessories with eBay's fitment check; finds say "fits your …" or "may fit".
POST /api/vinDecode a VIN (NHTSA): {vin} → {vin, make, model, year, trim, body, drive, engine, warning}.
GET /api/machines/ID/recallsSafety recalls: NHTSA for vehicles (make/model/year), the CPSC for other things (make, plus model or kind of product; each recall has match "model" or "type"); 400 for PCs and servers. source is "nhtsa" or "cpsc". Fields: {vehicle, recalls: [{campaign, date, component, summary, consequence, remedy, park_it, url}]}.
